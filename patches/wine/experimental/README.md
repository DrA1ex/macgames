# Experimental Wine work (not applied by default)

These research patches were implemented in this fork during the AoE IV and AoE II investigations. They are not FEX code ports and are not part of the upstream PR or the default application runtime. They modify Wine's existing macOS software-fault implementation and keep Wine's LGPL-2.1-or-later licensing; see `LICENSES/Wine-LGPL.txt` and `LICENSES/Wine-LICENSE.txt`.

- **0004: live exception context.** Cache process-wide segment selectors after the first Unix call and read thread-local FS/debug-register state live from the TEB, with shared offset assertions. This avoids repeating a Unix transition solely to supplement an already captured context.
- **0005: direct dispatch.** Enter Wine's normal exception dispatcher directly when no debugger is attached. Preserve native first-chance debugger delivery otherwise. Add the required unwind metadata to both dynamically aligned softfault thunks; without that metadata the first prototype failed nested unwind/finally tests.
- **0006: opt-in handler observer (diagnostics only).** Add a private observer registration point around existing VEH calls and the complete VEH chain, preserving LastError/LastStatus. An observer is never registered by default. `probes/handler_audit.c` supplies a bounded observer that returns without altering the game context or handler result. Compile with `AUDIT_FOCUSED` for the four selection-sensitive AoE II PCs; the unrestricted startup capture can fill its table and must not be treated as a complete gameplay profile. `probes/audit_behavior_probe.c` tests code snapshots, redirected continuation and LastError preservation. This patch is not required for the cache.
- **0007: AoE II fragment-ring cache.** Reuse the runtime's existing conservative immutable fragment cache with a separate `AoE2DE_s.exe` gate, `AOELAB_CODE_CACHE_AOE2=1` and the independently verified AoE II ring pointer at `0x144c943f0`. The handler's `& 0x7ffff` slot index and five-bit shift establish the same 16-MiB/32-byte layout as AoE IV. AoE IV's pointer remains `0x147af7ad0`. Unsupported instructions fall back to original execution. The application enables this only when an engine capability marker matches the native module's SHA-256; the bridge still pins the game EXE hash.

- **0008: AoE II register-only SSE2 fragments.** Extend the conservative relocator only for AoE II to accept the observed `movq`, `movdqa`, `paddq` and `pshufd` forms with prefix `66` and register operands (ModRM.mod = 3). Memory forms and unsupported control flow retain fallback; AoE IV keeps its original acceptance rules. The updated cache probe passes all 20,650 continuations, including 400 SIMD cases and 50 access violations with original fault PCs.

- **0009: selected AoE II non-returning veneers.** Populate four immutable entries in the existing software-fault bridge page. Experimental sidecar patch 0006 (in its own `experimental/` directory, excluded from default builds) can JMP through them without advertising a return into unreachable code. The veneers push the same synthetic fault return PC expected by the existing dispatcher; handler delivery is retained. All 46,000 selected-site context checks and the existing SEH/unwind/debugger checks passed. The first gameplay comparison reduced sidecar requests substantially, but median raw HUD interval remained 33.34 ms and the user still reported substantial lag; see LOCAL-AOE2.md.

The patches apply sequentially to Wine sources shipped with MacGames runtime4 (`Sources/wine-source.tar.gz`, SHA-256 `7be5819017b34f09670293f2be7ed9f4476734b8f42dab121a8b74e6619c92a8`). A fresh source-application check is recorded during publication; no rebuilt Wine binaries are stored in Git.

`probes/softfault_probe.c` and `probes/dispatch_probe.c` are original Windows test sources used for register/context, debugger and exception/unwind validation. The investigation validated GPR/flags/XMM/YMM, segment and live debug state, main/new threads, nested VEH, resumable SEH, stack unwind/finally and 4000 debugger first-chance events. Those tests passed in the development build; they establish compatibility rather than a gameplay performance result. Do not promote these patches to the default runtime on the strength of the microbenchmark alone.

This directory contains research source, not a complete general-purpose Wine build distribution. A PE ntdll build needs a matching Wine build tree and cross-toolchain; preserve original binaries and use an isolated Wine prefix. No address or executable-build guards are relaxed by these patches.

For 0007, `probes/aoe2_cache_probe.c` is built as `AoE2DE_s.exe` in an isolated test folder. It maps its own fake pointer and mutable ring, tests changing content, RIP-relative addressing, returns, unsupported branches and 50 access violations whose reported PCs must remain in the original ring. On the development machine, cache-off/on measured 16.568/1.415 microseconds per synthetic exception; all 20,250 continuations were correct, with 20,195 hits and five immutable entries. All 512 sampled live selection fragments canonicalized to three keys with relocation targets preserved. Context/debugger/unwind probes also passed on the rebuilt native Wine. These are microbenchmark and compatibility results. In a subsequent selected-group gameplay capture, the first cache variant recorded 869,961 hits in 20 seconds with no new entries. The median raw HUD interval was 33.34 ms versus about 100 ms in the earlier direct-dispatch capture; the user reported an improvement but substantial remaining selection slowdown. Separate launches and duplicated HUD history limit this comparison. Patch 0008 gameplay validation remains pending.

Rejected native D3DMetal resolve-skipping experiments are not enabled or shipped: the actual game did not meet the safe eligibility conditions, so no performance benefit was established. D3DMetal4 preview was also not selected for the default runtime.

The optional [AoE II selection-function cache](aoe2-function-cache/README.md) builds a separate pinned DLL/loader on top of the observer-enabled engine. It avoids repeated body rewriting on cache hits while retaining periodic original-handler validation and FH4 cleanup. The first successful «ПЕРФ» test and its limitations are recorded in LOCAL-AOE2.md. It is not installed by default.
